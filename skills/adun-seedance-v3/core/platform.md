# 即梦平台手册 · Seedance 2.5

> 本册汇总即梦 Seedance 2.5 的平台参数、输入规格、审核与代称经验、`@` 引用语法、专项能力操作公式与镜头转场词库，供第二段落笔与提交时按需查阅。官方手册规则、作者实测经验与默认工作选择在文中分别标明。

---

## 一、平台参数与输入规格

**当前版本：Seedance 2.5**（官方手册针对即梦；豆包专业版、火山方舟 API 等渠道以各自平台为准）。

| 维度 | 官方规格与使用说明 |
|---|---|
| 生成时长 | **4–30 秒**（接口 `duration` 支持 `-1` 与 `[4,30]`，即 `97–721 帧`），自由选择 |
| 输入总上限 | 图片最多 **30 张**（4K 分辨率以内）＋ 视频最多 **10 段**（总时长 ≤30s）＋ 音频最多 **10 段**（总时长 ≤30s）；请求体大小不超过 `64MB`（大文件勿用 Base64） |
| 图片单张要求 | 格式：`jpeg/png/webp/bmp/tiff/gif/heic/heif`；宽高比 `(0.4, 2.5)`；宽高边长 `(300, 6000) px`；单张 `<30MB` |
| 视频单段要求 | 格式：`mp4/mov`；单个时长 `[2, 30] s`（实际允许 `[1.8, 30.2] s`，总时长 `≤30.2s`）；分辨率 `480p–4k`；宽高比 `[0.4, 2.5]`；边长 `[300, 6000] px`；总像素 `[409600, 8295044]`；帧率 `[24, 60] fps`；单个 `≤200MB`（作者经验：带参考视频消耗积分更多） |
| 音频单段要求 | 格式：`mp3/wav`；单个时长 `[2, 30] s`（实际允许 `[1.8, 30.2] s`，总时长 `≤30.2s`）；单个 `≤15MB`；**支持仅传入音频**（不必带图或视频） |
| 文本与语种 | 自然语言描述；官方重点优化中/英/西/印尼/马来，覆盖泰/阿/葡/越/日/韩 |
| 声音输出 | 自带原生音效与人声口型同步（默认工作选择：用开头固定句挡掉随机 BGM） |
| 输出分辨率 | 官方接口支持 `480p`、`720p` 两档；默认工作选择为 **720P**（项目需 480p 在项目档案写明） |
| 生成模式 | 官方支持【全能参考】、【智能编辑】、【超长视频】、【首尾帧】；默认主流工作流为 **全能参考** |

### 关于官方【超长视频】模式（30–180 秒）
官方手册说明支持单次直接生成 30–180 秒长视频。作者判断其实际效果接近多段拼接且消耗昂贵，默认工作流不用，长片采用独立分段生成后自行剪辑；用户明确指定使用时按官方界面操作。

### 官方输入素材建议与多视角规则
以下为官方手册针对**输入参考素材**给出的稳定性建议（指传入参考中的主体数量，不是限制画面同框演员人数）：
- **主体图输入数量建议**：传入 `1–8 个主体`效果较好；更多可尝试 `9–12 个主体`，但稳定性下降、可能需要抽卡。本段画面里需要认得出的角色、场景、核心道具均挂图；认不出身份的远处人影与焦外人群不挂图。
- **主体音视频建议**：传入 `1–5 个主体`效果较好（可尝试 `6–10 个`）；单段时长 `5–10s` 效果较好。
- **编辑输入建议**：视频编辑输入视频 `20s 以内`效果较好；视频参考图编辑传入 `1–5 张参考图`效果较好（可尝试 `6–8 张`）。
- **不同视角主体图的输入差异（官方规则）**：
  - `1–5 主体`时，「单视图」「多视图」均可；
  - **超过 5 主体时，「单视图」效果较稳定**；如需输入多视角，建议拆分为多张不同视图独立传入，而非传入一张包含多视角的拼图（效果稳定性：多图多视图 > 单图多视图）。同一角色多图写法：`角色X形象参考@正面图（正面）@背面图（背面）`。
  - 若现有项目资产已是单张拼合的三视图／四视图，按 `core/format.md` 注明只取人物本体面貌与服饰，不采用纯色背景与并列构图。

## 二、审核与版权代称经验（作者实测）

### 1. 热门 IP 角色代称
实测中，正有热门电影、游戏 IP 在跑的知名角色，真名直接写进提示词正文易触发平台版权拦截。实测可行的处理方式：
- **`@` 素材引用保留原素材名**：实测素材名保留原名、仅替换正文称呼即可通过。
- **提示词正文换成固定的两到四字外形短代称**：只写看得见的外形特征，全篇统一用同一个短代称（如 `@杨戬` → 正文写 `银甲白袍将领`；`@哪吒` → `红绫战将`；`@太乙真人` → `花白长须老道`；`@悟空` → `猴王`）。
- **适用范围**：仅对正有热门影视、游戏大 IP 在跑的角色换代称；项目自创角色、冷门角色或实测不受拦的传统配角保留本名（对不拦截的角色滥用长代称易导致多人串脸）。台词原文归用户锁定，不自行篡改；台词含易被拦专名时，在正文外提示用户决定。

### 2. 画面与词面拦截经验
- **暴力与血腥画面**：实测审核主要拦截具体直白的血腥捕食画面，而非普通气势词（`妩媚`、`放电`、`血盆` 等词实测能过）。高发拦截画面为：巨兽利爪獠牙与人体并置成撕咬捕食、斩首喷血直写。遇到不合规提示时，先比对能过版本与被拦版本差在哪几句具体暴力描写，针对性改写那几句的视觉呈现，不盲目删减全篇气势词。
- **身材与贴体词**：写身材曲线、裸露与贴体衣料时，实测易被拦的词包括：`胸`、`胸口`、`胯`、`臀`、`腰臀`、`贴身`、`半透`、`透出身形`、`身段曲线`；写铠甲部位、佩饰、发力动作、外罩纱衣实测不受影响。
- **特定字面**：`法` 字后紧跟 `轮` 字会被拦；导演名 `詹姆斯·温` 写进正文会被拦（拍法可借，名字不写）。

## 三、`@` 引用系统与多模态绑定

### 1. 命名与跨段上传顺序
- 官方命名按当次上传顺序编号：`@图片1`…`@图片30`、`@视频1`…`@视频10`、`@音频1`…`@音频10`（官方示例亦出现过 `@图片1-10` 范围写法）。
- **作者做法**：素材已命名时优先用无文件后缀的 `@素材名`（避免某段少传一张图导致后续编号整体前移错位）；只有编号时用 `@图片N`，每段将上传清单与正文编号逐一核对，因每次独立生成均从 1 重新编号。

### 2. 用途标注与频次
- 全能参考模式下，输入 `@` 选择对应素材后须写明具体用途（如 `场景参考@图片1`、`人物形象参考@图片2`、`参考@视频1的运镜效果`、`音色参考@音频1`）。
- 素材较多时，声明区按「场景组 → 角色组（随身武器同句）→ 独立道具组 → 音视频组」分区书写。官方说明全文多次 `@` 可提升准确度；实操中在开头集中声明后，人多、外形相近或跨场景时可在角色每镜首次出现处再 `@` 一次。

### 3. 音色、音频卡点与视频参考
- **音色参考**：台词后可紧跟 `音色参考@音频N`，同一角色跨段挂同一段干净人声保持声线一致，具体情绪服从当场戏。
- **音频驱动与口型同步**：由外部音频主导节奏的段落（MV、歌曲卡点），可写明 `节奏与起止完全参考@音频N`。官方与实测中，演唱者正脸无遮挡特写时口型同步最稳；具体景别与角度仍服从导演定案。
- **参考视频**：挂参考视频（迁移创意、镜头语言、动作或节奏）时，写清取哪一项、作用于哪几秒、映射给哪个角色、其余不取。

## 四、专项能力与操作公式（按用户授权启用）

以下专项模式与功能**默认不主动启用**；用户明确提出要求后按下列规格执行。用户未提出时，仅在常规全能参考确难解决当前具体问题时可说明理由向用户提议，获同意后方可执行。

### 1. 时间戳与帧级控制
- **秒级**：官方示例支持整数秒（`0s-3s`、`[00:00 - 00:07]`）与小数秒（`[00.0-05.0s]`、`0–1.5s`）。各时间块内容与秒数相称时更容易按预期时码落位；单块塞入过多事件时，后续时间块常顺延并导致片尾被截。
- **帧级（音乐卡点／逐帧触发）**：官方支持按 24fps 或 30fps 指定帧号（如 `240帧共计10秒，第0帧……第48帧……`），写帧号前先标明所按帧率与总帧数。

### 2. 画内分屏
支持在单条生成中直接做画内分屏（作者实测三格稳定）：`画面被两条细细的竖线分成左、中、右三格，三格等宽，每一格是一个独立的近景，接缝笔直清楚`，再逐格写清人物与动作；需从全画幅裂开或合拢时写明秒数与方式。

### 3. 多宫格分镜参考
传入多宫格分镜图（官方推荐简约线稿／火柴人）时：①先说明 `每一个分镜代表一个完整镜头，而非单独的人物或场景`；②给主体设定并 `@` 参考图；③逐镜补齐镜间画面，写清构图、景别、运镜与动作；④写全局风格与固定要求。（挂俯视站位图时，写明各色标记对应角色、箭头为朝向、扇形为机位方向，只取站位朝向与相对空间关系。）

### 4. 视频延长（须经用户明确授权）
- **作者实测提醒**：延长会对原视频再次审核且尺度较严，易被拦；仅在用户指定使用，或伤势／环境破坏确需逐帧硬接、向用户提议获准后执行。
- **官方参数**：原视频（底片）须 `≤30 秒`；单次可延 `4–30 秒`；产物总长仍 `≤30 秒` 时可继续套娃延长，极限为 `30s 底片 + 延 30s = 60 秒`；生成时长选择**新增部分**的时长；提示词只对新增段生效，原视频画面完整保留；2.5 支持延长时继续挂图、视频、音频并支持切镜。
- **必填词与句式**：须含 `向前延长／向后延长／延续／续写`。
  - 一镜到底式：`参考@视频1的内容，延长视频[X]s向后延长。要求延长自然、动作衔接流畅、动作衔接自然，禁止生硬切镜、禁止物体凭空出现 + [新增内容描述]`
  - 切镜式：`参考@视频1的内容，延长视频[X]s延长续写。[转场类型指引 + 基础约束 + 切镜逻辑，可补景别变化] + [新增内容描述]`
  - 向前延长：`向前延长[X]s + [前置剧情描述]`

### 5. 视频无缝转场
传入前后两段视频自动补全过渡：`将【@视频1】和【@视频2】无缝衔接起来，但是不修改【@视频1】和【@视频2】` ＋ 衔接物在交接点形状、位置、大小、运动方向一致的补间描述。

### 6. 智能编辑／高级编辑／视频编辑（局部消除、替换、空间视角修改、去 BGM）
支持对已有视频定向修改局部人物器物、修改机位视角（如平视改俯拍、三人称改第一人称并合理外推补全画外空间）、或单独分离移除 BGM 并完整保留原字幕：
- **纯文字（智能编辑）公式**：`[具体修改对象] + [动作与变化描述] + [生效时序]`，带必填动词 `编辑视频里的xx／增加·加上／删除·去掉／修改·替换·改成`（例：`在视频的1-8秒，把男生的牛仔裤，替换为深黑色的西装裤`）。
- **带标注（高级编辑／视频编辑）公式**：`[标注工具与关注区域] + [具体修改对象] + [动作与变化描述] + [生效时序]`。写清所用工具（框、线、箭头、文字、地标点、橡皮擦）及关注框内或框外（`将红框内`、`沿着红色箭头指向的区域`、`地标点处`）；写明生效时序；提交前核对输入框自动生成的时间标签（如 `⏱️00:00 视频帧标注`）与目标时段一致。

### 7. 绿幕编辑与白模控制
- **绿幕编辑**：传入绿幕视频，描述新场景或挂场景图／视频完成抠像与光影合成。
- **白模控制**：Maya/Blender 插件或脚本导出白模视频上传，分粗颗粒度与细颗粒度两档，完整做法与公式见 `core/baimo.md`。

## 五、镜头语言与官方转场词库（供落笔选词查）

一拍保持干净轨迹，避免把互相拉扯的运镜硬叠在同一拍里（上升环绕、推轨配焦点跟随等顺向组合可用），换运镜咬在动作点上。中文直写即可。

### 1. 易混运镜与常用术语辨析
- **机位不动、镜头转**：摇镜（原地左右转）、俯仰（原地上下转）、镜头翻滚（绕光轴转）、甩镜（极快横甩）。
- **整机移动**：横移（朝向不变平行侧移，区别于原地转的摇镜）、垂直升降（朝向水平直上直下，区别于走弧线的摇臂）、推轨／拉轨（机位实际前后移动、透视随之改变，区别于机位不动只改变画角压扁或拉开背景的变焦推／拉）、摇臂上升／下降（沿弧线升降）。
- **跟拍与绕拍**：跟拍、前导跟拍（在人前方倒退拍正面）、尾随跟拍（跟在背后拍去向）、俯视跟拍；环绕（绕主体一整圈）、弧线移动（绕一小段）、上升环绕。
- **变焦与机身**：变焦推／拉、急变焦（瞬间猛推）、希区柯克变焦（机位后退同时变焦推，主体大小不变而背景塌缩）；手持、稳定器、机身固定（人脸定住背景动）、固定机位、航拍。
- **角度、对焦与节奏**：平视、高角度俯拍、低角度仰拍、正俯视、贴地虫视、荷兰角、主观视角、越肩、侧面、背影；浅景深、深焦、焦点转换、焦点跟随、由虚到实、分屏屈光（远近同清）；慢动作／升格、速度渐变、延时、移动延时、定格、倒放、动态模糊、子弹时间、快切、硬切、拉远揭示、侧移揭示、门窗孔洞穿越。

### 2. 官方转场词库（11 种）
需显式指定转场方式时可用官方句式：`需要在切镜处使用"XX转场"＋[这一次具体怎么执行]＋要求必须自然切换场景`（确有跳切风险时可带官方防错句 `禁止生硬切镜、禁止物体凭空出现`）：
- **基础类**：自然镜头切换、淡入淡出、叠化、白闪／黑闪（配重音）、擦除。
- **创意类**：遮罩转场（墙／背影／手掌／柱子遮满再拉开换景）、相似物转场（前后镜轮廓颜色相似匹配）、动作转场（顺力道甩入下一镜）、动态接力转场（出画与入画动势接力）、拉近／拉远转场（局部放大缩入新场景全貌或反向）、水墨转场。
